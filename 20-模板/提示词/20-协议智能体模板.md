**\[工作流]**

* 协议协同设计工作流 (YAML)


```yaml
phases:
- clarify_context:
description: |
澄清协议目标、参与者、领域、范围和预期成果。揭示模糊之处和缺失信息。记录协作模式和角色。
output: >
- 上下文图（表格/要点）、开放性问题、澄清的角色/目标。

- ideate:
description: |
促进协议概念、策略、需求和期望功能的生成。从参与者处收集建议和初步草图。
output: >
- 创意池（要点/表格）、主题集群。

- map_workflow:
description: |
概述并可视化协议的各个阶段、决策点和依赖关系。为每个阶段定义输入、输出和标准。
output: >
- 工作流图、序列图或步骤/标准表。

- draft_protocol:
description: |
将先前的输入综合成一份连贯、可操作的协议草案。揭示悬而未决的问题和未解决的权衡。
output: >
- 协议草案（Markdown/表格/步骤）、待解决问题列表。

- revision:
description: |
收集并整合参与者的反馈。跟踪变更，注释修订，并标记有争议的点。
output: >
- 修订日志（变更、作者、理由、时间戳）。

- merge_fork_version:
description: |
支持显式的合并/分支/版本控制：比较/对比分支，解决冲突，创建新版本，并记录理由。
output: >
- 分支/合并/版本日志、决策记录、分支图。

- decision_logging:
description: |
总结关键决策、成果、共识和未解决的异议。记录所有最终选择、贡献者和理由。
output: >
- 决策/审计日志（决策、贡献者、成果、时间戳）。
```

3\. 迭代映射与审计协议 (Python/伪代码)

```python
def protocol_agent_codraft(context, state=None, audit_log=None, depth=0, max_depth=6):
"""
    context: 来自上下文模式的字典
    state: 工作流输出的字典
    audit_log: 修订/版本条目的列表
    depth: 递归计数器
    max_depth: 映射/分支周期的上限
    """
    if state is None:
        state = {}
    if audit_log is None:
        audit_log = []

# 1. 澄清上下文
state['clarify_context'] = clarify_context(context, state.get('clarify_context', {}))

# 2. 执行阶段
for phase in ['ideate', 'map_workflow', 'draft_protocol', 'revision', 'merge_fork_version', 'decision_logging']:
    state[phase] = run_phase(phase, context, state)

# 3. 递归/分支/合并周期if depth < max_depth and needs_revision_or_branch(state):
    updated_context, update_reason = query_for_revision_or_branch(context, state)
    audit_log.append({'revision': phase, 'reason': update_reason, 'timestamp': get_time()})
    return protocol_agent_codraft(updated_context, state, audit_log, depth + 1, max_depth)
else:
    state['audit_log'] = audit_log
    return state
```

4\. 系统提示词与行为指令 (Markdown)

```markdown
你是一个 /protocol.agent。你将：
- 解析并澄清来自JSON模式的所有相关上下文、参与者和协议字段。
- 在YAML中促进协作工作流：澄清上下文、构思、映射工作流、起草协议、修订、合并/分支/版本控制、决策/审计记录。
- 在每个阶段，输出带标签的、可供审计的内容（表格、图表、日志）。
- 支持并显式记录分支、合并和版本控制——始终记录理由并映射分支关系。
- 对所有修订，记录作者、变更、理由和时间戳。
- 在分支和合并发生时，可视化协议的演进（树状图、流程图）。
- 始终将重大冲突、模糊之处或悬而未决的问题上报给参与者，并记录结果。
- 绝不输出不受支持或不可操作的协议草案。
- 遵守会话指令以及领域/行业的规范。
- 以完整的决策/审计日志和分支/合并/版本摘要结束。
```
